> 規格書寫「為什麼做」，這份寫「怎麼做」。技術細節有更好的做法就改，但第 1 節的決定不要動。

## 1. 已確認的決定（規格書 2.4 節的開放問題）

| 問題 | Gino 的決定 | 對設計的影響 |
|---|---|---|
| 部署形態 | **直接做雲端版** | 一開始就是 Web App 部署上雲，電腦開瀏覽器、iPhone 加主畫面即 PWA，同一份資料，不做第二次搬遷 |
| 暫付款結清 | **手動確認才轉** | 結清是一個明確動作，系統只負責提醒 + 提供按鈕，不自動改帳 |
| 估算金額修正 | **直接覆蓋，但留修改紀錄** | 主表永遠只有一筆乾淨資料；舊值進 `transaction_revisions` 稽核表 |
| 收入來源 | 工讀薪水、**家人給的**、**朋友還錢／代墊收回**、**實驗室計畫** | 收入分類同樣可自訂；「朋友還錢／代墊收回」要能連回原本那筆暫付款 |
| 每日記帳入口 | **LINE 訊息記帳**（主力）、**每天固定時間提醒**、**電腦端快捷輸入** | 見第 5 節 |
| 現有資源 | 已有 DeepSeek API Key、GitHub 帳號 | Supabase / Vercel / LINE Developers 需要新申請（都免費，用 GitHub 登入） |

## 2. 技術選型

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | Next.js（App Router）+ TypeScript | 前後端同一個專案，Vercel 部署零設定，API Route 直接當 LINE webhook 用 |
| 資料庫 | Supabase（Postgres） | 免費額度對個人記帳綽綽有餘，可用 GitHub 登入開通，有現成的資料瀏覽介面方便你自己看原始資料 |
| 部署 | Vercel | 連 GitHub 自動部署；內建 Cron 可做每日提醒 |
| PWA | manifest + service worker | iPhone Safari「加入主畫面」全螢幕；離線先寫入本地佇列，連線後補送 |
| 圖表 | Recharts | 客製彈性夠，能做出規格書要的「有質感、稍微酷一點」而不是企業報表感 |
| AI | DeepSeek（OpenAI 相容端點） | 規格書指定。2026-08-20 對著 API 確認：可用的是 `deepseek-v4-flash`／`deepseek-v4-pro`，用 flash。**一定要帶 `reasoning_effort: 'none'`**，否則慢 3～13 秒。細節見《踩過的雷.md》 |
| 桌面快捷 | AutoHotkey 腳本（Windows） | 瀏覽器做不到全域熱鍵，用一支小腳本按 Ctrl+Alt+J 直接彈出快記視窗 |

**存取控制**：規格書說不需要多使用者，但網址是公開的，所以加一道單一密碼登入（cookie 保存，手機登一次就好）。LINE webhook 走官方簽章驗證，不走密碼。

## 3. 資料模型（草案）

### `categories` — 分類
可自訂新增／改名／停用，不寫死 enum。
- `kind`：`expense` / `income`
- `is_fixed`：固定支出（房租、壇費）預設為 true，月結算時固定／變動分開算
- `sort_order`、`is_active`（停用而非刪除，避免舊資料失去分類）
- 種子資料：餐食、雜支、交通、食材採買、道場、醫療、健身、未分類、暫付款；收入側：工讀薪水、家人給的、朋友還錢／代墊收回、實驗室計畫

### `transactions` — 主表
- `date`、`amount`、`category_id`、`note`
- `kind`：`expense` / `income` / `advance`（暫付款）— 暫付款獨立，不併入月結算的一般支出
- `is_fixed`：預設繼承分類，可單筆覆寫
- `is_communal`：開伙標記，`amount` 記 0 但保留紀錄，月結算另外顯示「本月開伙 N 次」
- `is_estimated`：估算標記，跟已確認金額視覺上明顯區分
- `source`：`manual` / `line` / `web_agent`
- `raw_input_id`：指回原始那句話

### `settlements` — 跨月待結清追蹤
暫付款、媽媽借款待追蹤、押金待回收、補助待回收都走這裡。
- `status`：`open` / `settled`，`opened_at`、`settled_at`
- `settled_by_transaction_id`：結清時手動確認後，指向那筆收入或轉正的支出
- **只要有 `open` 項目，總覽頁最上方就常駐提醒，直到結清為止** — 這是規格書明講過去漏記過的痛點

### `transaction_revisions` — 修改稽核
每次改金額／分類／性質都留一筆（誰改的不用記，個人系統）。估算轉實際時舊值存這裡。

### `raw_inputs` — 原始語句
不管最後有沒有寫進正式紀錄都留著，含 AI 解析結果與信心值，之後用來檢討 prompt。

## 4. 分期

### P0　地基（先做，會需要你一起操作）
申請 Supabase / Vercel 帳號、建 GitHub repo、專案骨架、資料表建好、部署出一個能開的網址。
**產出**：一個你手機能打開的空殼網站。

### P1　核心迴圈 ← 第一個你真的用得到的版本
手動輸入表單、明細列表（篩選／搜尋）、事後修改與刪除、分類管理頁、密碼登入、PWA 加到主畫面。
**產出**：可以取代 Excel 日常輸入的最小系統。**這裡先停下來讓你實際用幾天再往下走。**

### P2　口語輸入 ← 2026-08-20 完成
DeepSeek 解析一句話 → 填進記帳表單給 Gino 核對 → 按下去才寫入 → 原句留存（`raw_inputs`，含有沒有被採用）。
分類用編號對回既有清單，對不上歸「未分類」。輸入框在記帳頁最上面，不另開頁。
原句檢視頁暫緩，要看用 `npm run db:studio`。

### P3　每日記帳入口 ← 2026-08-20 完成（桌面快捷鍵除外）
LINE Bot：傳一句話就記帳、回「改成 200」改金額、回「刪掉」刪掉、回「說明」看用法。
跟網頁不同，LINE 是**先寫入再讓人修正** —— 聊天視窗裡塞確認步驟太礙事，
回一句話就能改，等於把確認往後移。解析邏輯與網頁共用 `src/lib/interpret.ts`。
每日提醒排在台北 22:00（`vercel.json` 的 `0 14 * * *`），**當天已經記過就不發**。
Windows 桌面快捷鍵腳本還沒做。

### P4　視覺化
總覽頁（月度趨勢線、分類佔比）、待結清追蹤頁、月結算頁（固定／變動分開、開伙次數、暫付款獨立）。跨月比較排在最後。

### P5　資料進出
匯入過去的月度 Excel（五分頁結構），匯出同時提供 CSV 與 xlsx。

## 6. 之後要搬家：自己開一台 24 小時的伺服器

Gino 2026-08-18 提的：手機每次開都要等，延遲有感，想改成自己開伺服器。

### 先講結論

**慢的原因不是「資料庫在遠端」，是 Vercel 的免費方案會把伺服器睡掉。**
Vercel 是 serverless，沒人用的時候程式沒有在跑，你點開的那一下它才臨時起一個
執行環境、重新連資料庫，這段就是 1～3 秒的等待。之後連續操作就順了 ——
這跟「首頁 130ms」的量測對得起來，機房到機房只有幾毫秒，不是瓶頸。

所以：

- **搬到家裡的電腦不會比較快**，反而通常更慢。在家連 Wi-Fi 是快，
  但人在外面時要從外網繞回家，吃的是你家的「上傳」頻寬，而且電腦關機就整個斷掉。
  本機連 Supabase 還會卡死（見《踩過的雷.md》），這條路目前是不通的。
- **Gino 講的甲骨文方向是對的**：Oracle Cloud 永久免費方案給的是一台
  一直開著的機器（Ampere ARM，可選東京機房），程式跟 Postgres 裝在同一台，
  沒有冷啟動、資料庫是本機連線（不到 1ms）。這才是真正解決「開起來很久」的做法。

### 搬之前先做的（幾乎不用錢、也不用搬家）

這幾項先做完再決定要不要搬，說不定就夠了：

1. 首頁不要每次都重算全部。分類清單幾乎不會變，可以快取；
   目前每一頁都是 `force-dynamic`，等於每次點都重查資料庫。
2. service worker 先把外殼（版面、字體、圖示）快取起來，
   點開的第一眼就有東西，資料再補上。現在已經有 `loading.tsx` 骨架了，這是同一個方向。
3. ~~用 Vercel Cron 每 5～10 分鐘打一次 `/api/health`，讓它不要睡著。~~
   **這條行不通**：2026-08-20 查證，Vercel 免費方案的 Cron **一天只能跑一次**，
   寫 `*/10 * * * *` 會直接讓部署失敗。要保溫只能靠外部的免費排程服務
   （UptimeRobot 之類）定時打 `/api/health`。

### 真的要搬的時候，順序長這樣

1. 開 Oracle Cloud 永久免費帳號，建一台 Ampere A1 的 Ubuntu 機器，機房選東京。
2. 機器上用 Docker 跑三個東西：Next.js 本體、Postgres、Caddy（負責 HTTPS 憑證）。
3. 拿一個網址指過去（買一個便宜的 .com，或先用免費的動態網域）。
4. 從 Supabase `pg_dump` 一份資料倒進新的 Postgres，比對筆數與月結算數字對得上。
5. 設每日自動備份（`pg_dump` 存到物件儲存，保留 30 天）。**沒有備份就不要搬。**
6. 舊的 Vercel 版本先留著別刪，確定新的穩定跑一週再收掉。

> 風險要先講清楚：搬完之後備份、更新、憑證到期都是自己的事，
> Vercel 那邊是別人幫你顧的。這是拿「維護責任」換「速度與掌控」。
