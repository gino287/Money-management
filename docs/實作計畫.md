# 記帳系統 — 實作計畫

> 依據《規格書.md》+ 2026-08-10 與 Gino 的確認結果。
> 規格書寫「為什麼做」，這份寫「怎麼做」。技術細節有更好的做法就改，但第 1 節的決定不要動。

---

## 1. 已確認的決定（規格書 2.5 節的開放問題）

| 問題 | Gino 的決定 | 對設計的影響 |
|---|---|---|
| 部署形態 | **直接做雲端版** | 一開始就是 Web App 部署上雲，電腦開瀏覽器、iPhone 加主畫面即 PWA，同一份資料，不做第二次搬遷 |
| 暫付款結清 | **手動確認才轉** | 結清是一個明確動作，系統只負責提醒 + 提供按鈕，不自動改帳 |
| 估算金額修正 | **直接覆蓋，但留修改紀錄** | 主表永遠只有一筆乾淨資料；舊值進 `transaction_revisions` 稽核表 |
| 收入來源 | 工讀薪水、**家人給的**、**朋友還錢／代墊收回**、**實驗室計畫** | 收入分類同樣可自訂；「朋友還錢／代墊收回」要能連回原本那筆暫付款 |
| 每日記帳入口 | **LINE 訊息記帳**（主力）、**每天固定時間提醒**、**電腦端快捷輸入** | 見第 5 節 |
| 現有資源 | 已有 DeepSeek API Key、GitHub 帳號 | Supabase / Vercel / LINE Developers 需要新申請（都免費，用 GitHub 登入） |

## 2. 技術選型

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | Next.js（App Router）+ TypeScript | 前後端同一個專案，Vercel 部署零設定，API Route 直接當 LINE webhook 用 |
| 資料庫 | Supabase（Postgres） | 免費額度對個人記帳綽綽有餘，可用 GitHub 登入開通，有現成的資料瀏覽介面方便你自己看原始資料 |
| 部署 | Vercel | 連 GitHub 自動部署；內建 Cron 可做每日提醒 |
| PWA | manifest + service worker | iPhone Safari「加入主畫面」全螢幕；離線先寫入本地佇列，連線後補送 |
| 圖表 | **自己畫，不裝套件**（原訂 Recharts） | 需要的只有堆疊柱狀圖與甜甜圈：柱狀圖用 div + 百分比高度、甜甜圈用 SVG 的 stroke-dasharray，各二十幾行。Recharts 要 'use client' 而且會多背上百 KB 的 JavaScript，對一個在意冷啟動的手機 PWA 不划算。自己畫是純伺服器渲染、零 JavaScript、離線也能看 |
| AI | DeepSeek（OpenAI 相容端點） | 規格書指定。2026-08-20 對著 API 確認：可用的是 `deepseek-v4-flash`／`deepseek-v4-pro`，用 flash。**一定要帶 `reasoning_effort: 'none'`**，否則慢 3～13 秒。細節見《踩過的雷.md》 |
| 桌面快捷 | AutoHotkey 腳本（Windows） | 瀏覽器做不到全域熱鍵，用一支小腳本按 Ctrl+Alt+J 直接彈出快記視窗 |

**存取控制**：規格書說不需要多使用者，但網址是公開的，所以加一道單一密碼登入（cookie 保存，手機登一次就好）。LINE webhook 走官方簽章驗證，不走密碼。

## 3. 資料模型（草案）

### `categories` — 分類
可自訂新增／改名／停用，不寫死 enum。
- `kind`：`expense` / `income`
- `is_fixed`：固定支出（房租、壇費）預設為 true，月結算時固定／變動分開算
- `sort_order`、`is_active`（停用而非刪除，避免舊資料失去分類）
- 種子資料：餐食、雜支、交通、食材採買、道場、醫療、健身、未分類、暫付款；收入側：工讀薪水、家人給的、朋友還錢／代墊收回、實驗室計畫

### `transactions` — 主表
- `date`、`amount`、`category_id`、`note`
- `kind`：`expense` / `income` / `advance`（暫付款）— 暫付款獨立，不併入月結算的一般支出
- `is_fixed`：預設繼承分類，可單筆覆寫
- `is_communal`：開伙標記，`amount` 記 0 但保留紀錄，月結算另外顯示「本月開伙 N 次」
- `is_estimated`：估算標記，跟已確認金額視覺上明顯區分
- `source`：`manual` / `line` / `web_agent`
- `raw_input_id`：指回原始那句話

### `settlements` — 跨月待結清追蹤
暫付款、媽媽借款待追蹤、押金待回收、補助待回收都走這裡。
- `status`：`open` / `settled`，`opened_at`、`settled_at`
- `settled_by_transaction_id`：結清時手動確認後，指向那筆收入或轉正的支出
- **只要有 `open` 項目，總覽頁最上方就常駐提醒，直到結清為止** — 這是規格書明講過去漏記過的痛點

### `transaction_revisions` — 修改稽核
每次改金額／分類／性質都留一筆（誰改的不用記，個人系統）。估算轉實際時舊值存這裡。

### `raw_inputs` — 原始語句
不管最後有沒有寫進正式紀錄都留著，含 AI 解析結果與信心值，之後用來檢討 prompt。

## 4. 分期

### P0　地基（先做，會需要你一起操作）
申請 Supabase / Vercel 帳號、建 GitHub repo、專案骨架、資料表建好、部署出一個能開的網址。
**產出**：一個你手機能打開的空殼網站。

### P1　核心迴圈 ← 第一個你真的用得到的版本
手動輸入表單、明細列表（篩選／搜尋）、事後修改與刪除、分類管理頁、密碼登入、PWA 加到主畫面。
**產出**：可以取代 Excel 日常輸入的最小系統。**這裡先停下來讓你實際用幾天再往下走。**

### P2　口語輸入 ← 2026-08-20 完成
DeepSeek 解析一句話 → 填進記帳表單給 Gino 核對 → 按下去才寫入 → 原句留存（`raw_inputs`，含有沒有被採用）。
分類用編號對回既有清單，對不上歸「未分類」。輸入框在記帳頁最上面，不另開頁。
原句檢視頁暫緩，要看用 `npm run db:studio`。

### P3　每日記帳入口 ← 2026-08-20 完成
LINE Bot：傳一句話就記帳、回「改成 200」改金額、回「刪掉」刪掉、回「說明」看用法。
跟網頁不同，LINE 是**先寫入再讓人修正** —— 聊天視窗裡塞確認步驟太礙事，
回一句話就能改，等於把確認往後移。解析邏輯與網頁共用 `src/lib/interpret.ts`。
每日提醒排在台北 22:00（`vercel.json` 的 `0 14 * * *`），**當天已經記過就不發**。
Windows 桌面快捷鍵：`scripts/快速記帳.ahk`（Ctrl+Alt+J 跳輸入框 → 開瀏覽器並帶 `?say=`）。開發機沒裝 AutoHotkey，這支還沒實測過。

### P4　視覺化 ← 2026-08-20 完成
月結算頁 `/summary`：這個月花多少（變動／固定分條）、收入／暫付款／淨額三格分開、
近半年趨勢柱狀圖（點某個月就跳過去）、分類佔比甜甜圈 + 排行（點分類跳到篩選好的明細）、
月份可以前後翻。首頁的月結算卡片下半部也放了同一張趨勢圖的縮小版。
待結清追蹤頁在 P1 就有了。跨月比較還沒做。

### P4.5　首頁重整 ← 2026-08-21 完成
Gino 的要求：「點進去一開始想看到的應該是更乾淨的畫面」。
首頁改成三層：打招呼 + 今天一句話 → 一個口語輸入框 → 月結算與最近紀錄。
手動表單（性質／金額／分類／日期／備註）預設收合，按「自己填」才展開，
解析成功會自動展開讓人核對。收合用 grid `0fr → 1fr` + `inert`，表單一直掛著，
打到一半收起來不會弄丟。
新增 `getDayTotals()` 給招呼底下那一行用，是首頁第五支查詢，也是最便宜的一支。

### P4.6　看得出鬆緊 ← 2026-08-21 完成
- **跨月比較**（原本掛在「還沒做」）：本月比的是「到今天為止」對「上個月到同一天為止」，
  拿沒過完的月份去比上個月總額永遠會偏低，那是會騙人的數字。過去的月份則是整月對整月。
  首頁卡片與月結算頁共用 `CompareLine`。
- **月底預估**：目前日均 × 當月天數。前兩天與最後一天不預估。
- **最近七天小柱狀圖**（`WeekChart`）取代首頁卡片下半部的半年趨勢圖，半年那張留在月結算頁。
- **連續記帳天數**：今天沒記從昨天起算。

以上四項全部由**同一支** `getDailyTotals()` 餵，加上 `derivePulse()` 這支純函式換算，
首頁的查詢數維持五支。四項各查一支的話這頁要排隊九次。
還沒做：**分類層級的跨月比較**（「餐食比上個月多 1,200」）、常用組合一鍵記帳。

### P4.7　看得懂錢 ← 2026-08-21 完成

舊 Excel 匯進來之後，對了一次「Gino 手動維護的資訊」與「系統算得出來的東西」，
差三項。三項共用同一份 `getMonthlyTotals(6)`，首頁不多查、月結算頁只多查一支。

- **可用餘額**（`deriveBudget`、`BudgetBlock`）：收入 − 固定支出 − 已花的變動支出。
  交接摘要那句「可用餘額約 $4,251／月（扣固定支出後）」是整份 Excel 最實用的一格，
  也是唯一往前看的數字。Gino 的收入不規律又常常月底才補登錄，所以當月收入是 0 的時候
  改用前三個月有收入的月份平均，並在畫面上標明「收入是估的」；兩邊都沒有就整塊不顯示。
- **累積結餘**（`deriveCumulative`、`CumulativeChart`）：每月結餘累加。
  單月結餘看不出趨勢，累積線才看得出斜率。這是唯一會出現負值的圖，
  所以零線畫在中間、正往上負往下。暫付款不計入。
- **固定支出漏記提醒**（`getFixedCheck`、`FixedCheck`）：上個月有、這個月還沒有的固定分類。
  **而且會從可用餘額裡先扣掉** —— 房租沒記就說「還可以花 20,445」是騙人的。
  刻意不做「每月自動帶入」：金額會變（壇費 650 → 700），自動記會安靜地記錯。
  首頁只比得出總額（省一支查詢），月結算頁才指名道姓。

順手修掉 `formatSigned(0)` 會印出「−0」的問題 —— 以前沒有 0 元的非開伙紀錄，
匯入「回家沒花費」那種之後才冒出來。

### P4.8　待結清做完整 ← 2026-08-21 完成

Gino 用了一天之後提的兩個問題，兩個都是真的設計缺陷：

**一、結清是二元的**。借出 1,000、對方分兩次各還 500，系統沒地方記。
解法刻意**不是**「讓待結清項目的金額可編輯」—— 那會變成第二本帳，跟明細對不起來。
改成 `transactions.settlement_id`：每一次收回都是**真的一筆交易**再綁回該項目，
待結清頁的「已收 1,000」是 `sum()` 出來的。錢永遠只有一份紀錄。
收滿了不自動結清，只把按鈕文案換成「收齊了，標記結清」（維持 2026-08-10 的手動確認原則）。
方向決定性質：`receivable` 收回記收入、`payable` 還款記支出，否則月結算會把還款算成收入。

**二、首頁的常駐提醒讓人想按掉**。Gino 的原話：「押金我要等到明年退租才拿得到，
那個沒結清一直放在首頁，我會很忍不住想要把他結清消除，但又無法。」
這是設計逼使用者造假，很嚴重。加 `settlements.due_month`（`YYYY-MM`，可空），
`isDue()` 決定首頁與導覽列吵不吵：**到期、過期、沒寫時間**三種才吵。
沒寫時間的故意要吵 —— 連自己都說不出什麼時候回來的錢最容易被忘記。
規格書 2.2 的「一直看得到」沒有違背：完整清單永遠在 /settlements，分「該追的」與「還早」兩區。

`drizzle-kit push` 在這個資料庫上會崩（見《踩過的雷.md》），這兩個欄位是手寫 SQL 加的。

### P5　資料進出
匯入過去的月度 Excel（五分頁結構），匯出同時提供 CSV 與 xlsx。

**已經備好的部分（2026-08-21）**：

- `匯入/` 資料夾（附 README），內容進 `.gitignore` —— 真實收支數字不推上 GitHub
- `scripts/檢查excel.mjs`（`npm run check:excel`）：唯讀的結構檢查工具，不碰資料庫、
  不需要 `.env.local`。印出每個分頁的標題列、逐欄型別統計、少量樣本、以及分類欄出現過的值
- `exceljs` 4.4（devDependency）。**只給腳本用，不進 Next.js bundle** ——
  匯入是一次性遷移，做成 CLI 比做上傳頁面單純太多，也不必擔心 serverless 的檔案大小
- 註記：`npm audit` 會報 exceljs 依賴的 `uuid < 11.1.1`（傳 `buf` 參數時缺邊界檢查）。
  正式相依樹是 0 個漏洞，這支只在 Gino 自己的機器上讀自己的檔案，不修

**匯入程式（2026-08-21 晚上）**：`scripts/匯入.mjs`（`npm run import`，加 `-- --write` 才真寫）。
Gino 給了 3~8 月六個檔，實際結構跟口頭描述一致：五分頁，只有「記帳明細」「收入明細」
是原始資料，「分類彙總」「月結算」整頁公式、「交接摘要」是敘述，都不匯 —— 系統自己會算。

跟 Gino 對過的六個決定（2026-08-21）：

1. 年份一律 2026（3 月那張的橫幅誤植成 2025，同檔案的交接摘要寫 2026）
2. 3~7 月整月匯，8 月只到 **8/11**。8/12 起 Gino 已經在系統裡自己記了，
   而且 8 月的 Excel 裡就有 `8/12 健身房 50`、`8/17 晚餐 90` 這兩筆重複
3. 開伙是專有名詞＝在家煮飯這餐沒花錢。備註「在家／開火／開伙」才算開伙；
   「回家沒花費」「學長請客」照樣記 0 元但 `isCommunal=false`
4. 「媽媽借款 30,000」不進收入，記成 `settlements` 的 payable
5. 分類照 Excel 原名新增七個支出、七個收入分類
6. 沒有確切日期的（「7月」「3月初」「6/19~21」）挑一天，原文寫進備註

實作上要小心的幾點（都踩過）：

- **合併儲存格**：`A44:C44` 這種列，exceljs 會讓範圍內每一格都回同一個值。
  不擋掉的話「4月底」會變成一個分類、日期會被當成項目。用 `cell.isMerged` 判斷
- 每張明細分頁最後是「本月合計」→ 空列 →「固定支出（另計）」→ 租金／壇費。
  合計要跳過，租金壇費要當成 `isFixed` 的支出記在 1 號，
  「（已含上方）」那幾列是 0 元提醒，記了會重複計
- Excel 的「暫付款」是分類，系統的是 `kind`。三筆改掛真分類（雜支／娛樂／住宿）＋
  `kind='advance'`，這樣月結算才不會把它算進支出
- 寫入標 `source='import'`（為此在 `TRANSACTION_SOURCES` 加了這個值），
  整批退回只要 `delete from transactions where source = 'import'`
- 去重鍵是（日期＋金額＋分類＋性質＋備註），重跑不會變兩份

**對帳結果**：3 月 13,532、4 月 11,717 跟 Excel 的月結算完全一致。
5 月我算 21,062、Excel 是 22,062，差額正是「新北課程訂金 1,000」——
那筆在系統裡是暫付款，本來就不該算進支出（6 月退回也有記到），差得有道理。

### P6　多人 ← 2026-08-26 完成

Gino 的媽媽也想用。跟他確認過兩件事（2026-08-26）：

1. **各記各的，不是共用一本** —— 兩本完全獨立的帳，彼此看不到對方任何東西
2. LINE 那邊他還不確定媽媽要不要用，所以資料結構做好、綁定流程做好，
   但不強迫綁；不綁一樣可以用網頁記帳

**資料模型**：新增 `users`（名字、密碼雜湊、`line_user_id`、`is_active`）。
`categories` / `transactions` / `settlements` / `raw_inputs` 各加 `user_id not null`，
外鍵用 `restrict` 不是 `cascade` —— 刪掉一個人＝刪掉他好幾個月的帳，
那不該因為一句 `delete from users` 就安靜發生。要停用請用 `is_active`。

分類唯一鍵從 `(name, kind)` 改成 `(user_id, name, kind)`，索引全部改成以 `user_id` 開頭。

**關鍵設計決定：`userId` 是每一支查詢必填的第一個參數。**
另一個做法是讓查詢自己讀 cookie 算出「現在是誰」，呼叫端一行都不用改 ——
沒有採用，因為漏掉一支查詢時它不會編譯失敗、不會丟錯，只會安靜地把別人的帳
顯示給錯的人看。改成必填參數之後少傳一支就編不過。理由完整版在《踩過的雷》。

**登入**：從「一組共用密碼」變成「名字 + 密碼」，密碼用 PBKDF2-SHA256（21 萬次）
雜湊存資料庫。session 憑證帶著 `userId`，proxy 只驗簽章（它跑在 edge，碰不得資料庫），
「這個人還在不在、有沒有被停用」在 `src/lib/session.ts` 的 `currentUser()` 確認，
每一頁都會經過 `(app)/layout.tsx` 走到它。

代價講清楚：**沒辦法單獨把某個人踢下線**。憑證是自己會過期的簽章（90 天），
不是查表查出來的 —— 那是為了讓 proxy 不用每個請求都碰資料庫（連線數見 `src/db/index.ts`）。
要讓所有裝置立刻重登，只能換 `AUTH_SECRET`。

**LINE**：一支官方帳號服務所有人，靠 webhook 帶的 `source.userId` 反查 `users`。
不用一人開一支 bot。沒綁定的人不記帳，但會收到一則「這是你的代號，拿去請人開通」——
那串代號除了問這支 bot 之外拿不到，沒有這一段就沒辦法幫別人開通。

**開帳號沒有網頁入口**，只有 `npm run user -- add 名字`（`src/db/users.ts`）。
幾個人在用的東西，公開註冊入口只是多一個誰都打得到的寫入端點。

**遷移**：`npm run db:multiuser`（預設預演，`-- --write` 才真寫）。
現有的 397 筆帳、29 個分類、3 筆待結清、33 筆原始語句全部歸給第一個帳號，
密碼沿用原本的 `APP_PASSWORD`，`LINE_USER_ID` 順便綁上去 —— Gino 那邊完全無感。

**驗收**：`tests/ledger.spec.ts` 新增兩條，都是拿真的第二個帳號驗的：
另一個人在首頁、明細、搜尋、直接打網址、CSV 匯出都拿不到你的帳（直接打網址要 404），
以及他記的帳不會混進你的月結算。

## 6. 之後要搬家：自己開一台 24 小時的伺服器

Gino 2026-08-18 提的：手機每次開都要等，延遲有感，想改成自己開伺服器。

### 先講結論

**慢的原因不是「資料庫在遠端」，是 Vercel 的免費方案會把伺服器睡掉。**
Vercel 是 serverless，沒人用的時候程式沒有在跑，你點開的那一下它才臨時起一個
執行環境、重新連資料庫，這段就是 1～3 秒的等待。之後連續操作就順了 ——
這跟「首頁 130ms」的量測對得起來，機房到機房只有幾毫秒，不是瓶頸。

所以：

- **搬到家裡的電腦不會比較快**，反而通常更慢。在家連 Wi-Fi 是快，
  但人在外面時要從外網繞回家，吃的是你家的「上傳」頻寬，而且電腦關機就整個斷掉。
  本機連 Supabase 還會卡死（見《踩過的雷.md》），這條路目前是不通的。
- **Gino 講的甲骨文方向是對的**：Oracle Cloud 永久免費方案給的是一台
  一直開著的機器（Ampere ARM，可選東京機房），程式跟 Postgres 裝在同一台，
  沒有冷啟動、資料庫是本機連線（不到 1ms）。這才是真正解決「開起來很久」的做法。

### 搬之前先做的（幾乎不用錢、也不用搬家）

這幾項先做完再決定要不要搬，說不定就夠了：

1. 首頁不要每次都重算全部。分類清單幾乎不會變，可以快取；
   目前每一頁都是 `force-dynamic`，等於每次點都重查資料庫。
2. service worker 先把外殼（版面、字體、圖示）快取起來，
   點開的第一眼就有東西，資料再補上。現在已經有 `loading.tsx` 骨架了，這是同一個方向。
3. ~~用 Vercel Cron 每 5～10 分鐘打一次 `/api/health`，讓它不要睡著。~~
   **這條行不通**：2026-08-20 查證，Vercel 免費方案的 Cron **一天只能跑一次**，
   寫 `*/10 * * * *` 會直接讓部署失敗。要保溫只能靠外部的免費排程服務
   （UptimeRobot 之類）定時打 `/api/health`。

### 真的要搬的時候，順序長這樣

1. 開 Oracle Cloud 永久免費帳號，建一台 Ampere A1 的 Ubuntu 機器，機房選東京。
2. 機器上用 Docker 跑三個東西：Next.js 本體、Postgres、Caddy（負責 HTTPS 憑證）。
3. 拿一個網址指過去（買一個便宜的 .com，或先用免費的動態網域）。
4. 從 Supabase `pg_dump` 一份資料倒進新的 Postgres，比對筆數與月結算數字對得上。
5. 設每日自動備份（`pg_dump` 存到物件儲存，保留 30 天）。**沒有備份就不要搬。**
6. 舊的 Vercel 版本先留著別刪，確定新的穩定跑一週再收掉。

> 風險要先講清楚：搬完之後備份、更新、憑證到期都是自己的事，
> Vercel 那邊是別人幫你顧的。這是拿「維護責任」換「速度與掌控」。
