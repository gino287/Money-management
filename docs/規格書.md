# 記帳系統規格書

> 這份文件描述「為什麼做這個系統」「哪些規則不能變」「體驗上想達成什麼」。
> **刻意不寫死技術選型、資料庫細節、頁面拆分、實作分期順序** —— 這些交給你（Claude Code）依據實際狀況研究、規劃、決定。遇到不確定的地方，直接問 Gino，不要自己腦補。

---

## 1. 這個系統為什麼存在

Gino 目前用 Excel（每月一個檔案，五分頁：記帳明細／收入明細／分類彙總／月結算／交接摘要）手動記帳，已經維持好幾個月，習慣很穩定。這次要做的不是取代這套邏輯，而是：

1. 讓輸入更方便 —— 除了手動填表，也能「隨口講一句話」讓 AI 自動判斷並記錄
2. 讓資料更好匯入匯出 —— 舊的月度 Excel 檔案要能匯入，未來也要能匯出
3. 讓數據視覺化 —— 現在的 Excel 看不出「感覺」，只有數字
4. 能在 iPhone 上方便操作 —— 不需要上架 App Store，PWA（加到主畫面、全螢幕體驗）就好

這是個人使用系統，不是要做成產品給別人用，不需要考慮多使用者、權限管理這類複雜度。

## 2. 不能變的資料慣例

這些是 Gino 實際記帳好幾個月累積下來的規則，資料模型設計時務必保留這些語意，但**用什麼欄位、什麼表結構去實現，你自己判斷**。

### 2.1 分類
目前在用的類別：餐食、雜支、交通、食材採買、道場、醫療、健身。
分類要可以之後由 Gino 自己新增／調整，不要寫死成 enum。

### 2.2 特殊規則
- **開伙（communal cooking）記 0 元** —— 這類支出不算實際花費，但仍要留紀錄（不是不記，是記金額為 0）
- **暫付款要獨立分類**，不能跟一般支出混在一起計算月結算
- **估算金額要有標記**，跟已確認的實際金額區分開，之後有真實數字要能回頭修正
- **固定支出（房租、壇費等）跟變動支出分開計算**，月結算時兩者都要看得到
- **跨月待結清項目**要能追蹤，例如「媽媽借款待追蹤」「押金待回收」「補助待回收」—— 這種東西容易在月結算時被忽略，過去就出現過漏記的狀況，新系統要讓這類項目「一直看得到」直到結清為止

### 2.3 使用習慣
- Gino 偏好**週更**，不是每天記，介面不該假設使用者每天都會打開
- 偶爾會有**事後修正**的情況（例如發現某筆記錄性質判斷錯了），修正要方便，不能只能刪掉重建

### 2.4 尚待確認（動工前先問 Gino，不要自己假設）
- 收入來源除了工讀薪水，還有哪些常見類型？（補助／家人給的／朋友還錢）
- 暫付款結清之後，希望系統自動轉一般支出，還是手動確認？
- 估算金額之後有了實際數字，是直接覆蓋，還是留兩筆做對照？

## 3. 輸入方式

系統要支援兩種輸入，最終都寫進同一套資料，不要變成兩套邏輯：

1. **手動輸入**：類似表單，填日期、金額、分類、備註
2. **口語輸入（Agent）**：用 DeepSeek V4，Gino 隨口講一句話（例如「剛剛跟朋友吃午餐花了 150」），AI 判斷出金額、分類、日期、備註，結構化後寫入

### 對 Agent 層的要求
- 分類判斷要比對 Gino 既有的分類清單，不要讓 AI 自己發明新分類；對不上時歸到「未分類」，讓 Gino 事後調整
- 寫入前建議有一個確認步驟（顯示「幫你記了：餐飲 -150，對嗎？」），尤其上線初期，一方面抓 AI 判斷準不準，一方面避免口語誤判（金額聽錯很致命）
- 原始輸入的那句話要保留下來（不管有沒有寫進正式紀錄都建議留著），方便之後回頭檢查 AI 判斷邏輯、或用來微調 prompt

## 4. 視覺化需求

這是 Gino 特別在意的部分，現有 Excel 完全沒有視覺化。

### 4.1 想看到的內容（優先序高到低）
1. **月度趨勢線** —— 看每月花費變化
2. **分類佔比** —— 這個月錢花去哪
3. **待結清項目提醒** —— 暫付款、待追蹤款項要一目了然，不能被埋掉
4. 跨月比較（這個月 vs 上個月／去年同期）—— 優先度較低，但也想要

### 4.2 呈現方式
- **不需要擠在單一畫面**，可以拆成多個頁面／區塊，例如總覽頁 + 明細頁 + 待結清追蹤頁，你依內容量自己規劃合理的資訊架構
- 圖表可以做得**豐富一些**，Gino 明確表示不想要太陽春；風格上傾向**有質感、稍微「酷」一點**，不是死板的企業報表感，但也不需要花俏到影響資料可讀性 —— 這個分寸你可以先做一版出來，讓 Gino 看了再微調方向
- 手機（iPhone，PWA）上要能正常閱讀操作，不是只顧桌面版好看

---

## 5. 平台需求

- **PWA**：Gino 只需要在自己的 iPhone 上用得方便，不需要上架 App Store。做到 Safari「加入主畫面」後全螢幕可用、離線也能記帳（至少能先記、之後同步）就夠
- 不需要多使用者系統、不需要帳號權限管理，這是個人系統

---

## 6. 資料遷移

Gino 手上有過去好幾個月的月度 Excel 記帳檔案（結構如第 2 節描述），系統要能把這些歷史資料匯入。這部分不急，但資料模型設計時要考慮到「未來要能吃進這種格式」。

同時系統也要能**匯出**，格式不限制，你評估怎麼做對 Gino 最方便（沿用 Excel 格式，或提供更泛用的 CSV，都可以在規劃階段跟 Gino 確認）。

## 7. 給 Claude Code 的執行原則

- **請自己規劃分期**，不要一次把所有功能做完。建議思路是：先讓「記錄 + 查看」這個核心迴圈（手動輸入 + Agent 輸入 + 基本列表）能跑起來，讓 Gino 實際用過、有感受之後，再逐步加上視覺化、待結清追蹤、歷史資料匯入、匯出這些。但實際怎麼切、切幾個階段，由你判斷。
- **技術選型、資料庫結構、頁面拆分，你自己研究決定**，不用等 Gino 給規格 —— 上面列的是「不能變的規則」，不是技術規格。
- 遇到第 2.4 節列的開放問題，或任何規劃中發現的模糊地帶，**直接問 Gino**，不要自己猜。
- 過程中如果發現本文件跟實際情況有衝突（例如 Excel 裡藏著本文件沒提到的規則），以實際資料為準，並回報給 Gino。
